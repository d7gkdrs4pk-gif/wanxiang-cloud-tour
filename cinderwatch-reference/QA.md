# R1 独立参考场景验证

本轮按用户最新要求暂停凤鸣山门局部修改，提供参考视频场景的独立可操作入口。来源是kevintngo的MIT开源Cinderwatch历史提交8313bb2；26项原作源码逐字节保留，模型、材质、灯光、相机和原作塔防逻辑未重制或替换。不是视频背景、不是凤鸣山门H37，H36/H31/H29仍保留。

## 同机位画面

seed=4，第5131个1/60秒模拟步，1920×1080虚拟画幅/DPR1，原作内部960×540。生命17、金币23、击杀58、第4波，23怪+10队列；桥、六塔、城堡、树木、岩壁和灯光区域与官方历史视频首帧一致。未经warp的相位偏移不足.01px。原1920×1080 RGB SSIM .880118，等比例640×360 SSIM .970346；视频编码、颗粒和声音按钮文案仍有差别，因此不称逐像素相同。来源与指标见evidence/official-comparison.json。参考后段包含剪辑，直播战局不会按剪辑的墙钟时刻跳跃。

证据并排图仅使用原作者官方MIT演示文件，不包含用户私人云盘录像或帧。

## 实际操作与性能

- Chromium156 / SwiftShader云软件GPU，844×390触屏模拟：用原生touchscreen.tap点已有炮塔，打开菜单，出售，再原地建弓塔；塔数6→5→6，原有金币判定生效。连续15.03秒实际运行，9帧，约0.592 FPS。录屏会增加此云软件环境开销。错误0，失败请求0。
- WebKit26.5/WPE云软件GPU，844×390触屏模拟：正常加载同版场景、原生点按炮塔打开菜单，并实时运行12秒。43帧，约3.586 FPS；中位帧间隔见webkit-test.json。390×844竖屏完整构图留边，旋转不会换机位。错误0，失败请求0。
- 这些是云Linux软件GPU的真实测量，不是iPhone硬件或微信真机；未验证iPhone流畅度，也不将1/60模拟步或录像编码帧率当作实测FPS。

原作桌面按钮依赖上帧hover，host在pointerdown捕获阶段用当次触点、dt=0刷新其HUD命中，再交原作处理，避免手机点菜单无响应。载入异常/运行异常/图形上下文丢失均显示恢复按钮，恢复层可点。派生engine由build-host.py重建，仅固定DPR并转发错误，不改原作游戏代码。
