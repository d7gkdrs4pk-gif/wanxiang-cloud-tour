# H.32 山门上部屋檐修订

当前 H.32 样关默认启用 `light` 受光材质模式。PBR 只保留为对照选项，不是样关默认；用户美术验收仍未据此标为通过。

## 与实际入口一致的调用

`sample/main.js` 在山门应用最终世界变换、调用现有 `env.styleGate(gate)` **之后**，在 `prepareRoof(gate)` 和 `createRoofOcclusion(gate)` **之前**调用：

```js
if (params.get('roofFinish') !== '0') {
  finishGateRoof(gate, {
    shading: params.get('roofPbr') === '1' ? 'pbr' : 'light'
  });
}
```

- 正常入口：修订屋檐，`light` 模式。
- `?roofPbr=1`：相同修订几何，PBR 材质对照。
- `?roofFinish=0`：停用上部修订，显示原屋檐几何；其他 H.32 修复仍保留。

底层模块 `finishGateRoof(gate)` 不传 `shading` 时仍默认 PBR，便于单独 A/B；正式样关始终按上面的入口代码显式传入 `light`。在同一 gate 上切换参数会先还原、释放前一个修订组件。`restore()` 可移除组件并恢复原几何引用。

## 受光、颜色与近景雾

`light` 模式的瓦面及墨檐/木构使用 `MeshLambertMaterial`，接收原场景同方向的暖白主光和冷青环境光，保留曲面法线、每瓦顶点色、低频色差及檐下深色处理，不是无光色板。小古金脊端保持 `MeshStandardMaterial`，系统字体木匾仍为 `MeshBasicMaterial`。

root 在当前场景对 `light` 做了线性材质颜色校准：瓦面 `color.setRGB(3.2,3.2,3.2)`，木构 `color.setRGB(2,2,2)`。这些系数只乘到该模式的两个建筑材质，不改全场曝光、灯光、相机或原下部材质。PBR 模式不使用此补偿。

两个模式的全部新增材质（包括木匾）均显式 `fog=false`，与原 gate 的近景处理一致，避免屋面被远景雾洗淡。早期候选截图在此校正前拍摄，不能直接代表当前颜色与体积。

## 几何和真实台阶保留

来源为本项目现有 `assets/sample-lod/gate.glb`，按 `assets/sample-lod/metadata.json` 的原世界变换测量。原 GLB 和缓存导航均不写入。所有最低世界顶点不高于 Y=1.2 的原三角面保留：**21,403 个真实低层三角**的原位置、法线、UV 和有序索引逐值一致；可行走石阶、基座、世界通行范围不变。

源 metadata 的 21,419 个“protected”面还包括 16 个上部极值保护片，并非全部是低层石阶。修订将这些上部片与旧屋面一起替换，避免遗留悬空碎片；不是删掉台阶。

新上部为连贯厚曲面、116 条筒瓦行、每行六枚真实搭接短瓦、瓦唇、墨色檐口、深木柱梁/曲拱及少量旧金脊端。正常 DOM 环境含木匾共新增 **22,062 三角／4 材质与 draw**；保留低层加新组件为 **43,465 三角**，原 LOD 为 33,000。无 DOM 的几何检查不生成木匾，为 21,936 新三角／3 draw。`candidate-structure.json` 保存几何检查与实际使用索引的世界范围，不用未引用的旧屋顶顶点虚报范围。

PBR 与 `light` 的位置、法线、顶点色、索引缓冲完全相同；区别是瓦面/木构的材质类型、以及上述明确的 `light` 颜色校准。下部保留和 `restore()` 已做 CPU 精确检查。材质模式等价几何数据保留于 `/workspace/qa-h32/gate/light-mode-cpu.json`；该记录不是当前色调或帧率验收。

## 来源与验证范围

所有新屋面、瓦片、檐口、脊饰、柱梁和曲拱均为本项目原创代码，无外部模型、贴图或付费生成。木匾“凤鸣”由系统 CJK 字体在本地 canvas 渲染，未使用外部字图或分发字体文件。

第二版曾在 390×844、原 FOV39／原跟随偏移 `(6,27,15)` 下做正常整屏浏览器检查，运行错误0，人物到达原真实阶面 Y≈.713。后续帧率对照显示 PBR 候选成本偏高，因此正式默认改为受光轻材质；最终颜色、体积与帧率应以 root 最新同机位截图和计时记录为准，不沿用早期候选结论。

云端 Linux 软件图形栈的 Chromium/WebKit 手机尺寸模拟不等于 iPhone 硬件或微信内嵌浏览器真机测试。CPU 几何检查、单次渲染提交耗时和视频编码帧率都不能代替实际渲染帧率，也不能单独作为美术通过证明。
