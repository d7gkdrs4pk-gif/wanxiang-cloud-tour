# H.30 render-only mobile LOD

These assets are derived from this project's existing `terrain-001/terrain.glb` and `gate-001/gate.glb`. No external models or images were added. The source glTFs stay unchanged and remain the authoritative geometry for navigation/height sampling; the sample uses their baked navigation cache at runtime.

| Asset | Source triangles | Render triangles | Download bytes |
| --- | ---: | ---: | ---: |
| terrain.glb | 75,454 | 30,000 | 1,681,172 |
| gate.glb | 75,702 | 33,000 | 1,969,984 |

Total models: 3,651,156 bytes. Each is one mesh/one material, plain glTF2 with no decoder extension. Original bounding-box extremes are retained exactly. `metadata.json` includes source SHA256, original glTF Y-up bounds, normalization scale/translation/4×4 matrix, and the original terrain's central probe height. The gate's lower 21,419 source triangles, including the real stairs below final worldY1.2, are retained separately from the simplified roof before joining the export mesh. Original UVs remain; only near-coincident duplicate vertices in the simplifiable region are welded.

The sample's texture budget is explicit: original base-color images are resampled from4096 to1024 and encodedJPEG90; normal/ORM are resampled to512 and retainedPNG without additional JPEG compression. `validation.json` reads the actual embedded images back to verify dimensions/MIME, rather than trusting exporter settings.

Rebuild from repository root:

```sh
blender -b --factory-startup --python .github/scripts/build_sample_lod.py
```

Requires Blender and ordinary Python with Pillow. The generator calls `.github/scripts/build_sample_lod_post.py` because Blender's automatic texture export can choose JPEG for a packed ORM source. Source assets are never overwritten.

`navigation.json` is generated by the sample-navigation workflow from original geometry, not from these render LOD meshes.
