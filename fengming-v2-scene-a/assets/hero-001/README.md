# 林砚 H31：连续衣形与正常手机镜头修订

当前运行模块：`../../sample/hero.js`。H31 完整造型生成源保留在 `../../../.github/scripts/lib/linyan-h31-generator.mjs`；H32 将相同几何预烘焙到同目录 `linyan-h31-baked.js`，避免手机每次启动现场构造曲面。H30旧男主保留在 `../../sample/archive/h30-hero.js`，旧说明见同目录 `H30_README.md`。本轮仍为自有几何、骨架、顶点色与动作，没有下载他人的角色当作林砚。

设定仍是本工程 `project/GAME_DESIGN.md` 的男性铃师林砚：朱红袍服、少量凤金、束发与悬铃凤刃。全高上限1.485，FOV39/相机偏移(6,27,15)和原出生位未变，不能用放大人物替代质量判断。

## 对H30质量问题的实际处理

- 删除硬板肩背和拼接上袖。上衣躯干与左右连肩袖是同一个SDF smooth-union曲面，有真实领孔、梯度平滑法线、连续胸背/肩部蒙皮权重。不是把原肩板加细分或堆肩球。
- 下袍由有厚度、纵褶、前开襟的连续弧面构成，顶端随髋、下缘混合腿和袍骨权重，迈步时连续弯曲，替代H30外翻三角卡纸式裙片。
- 袖口、手和靴重塑为圆柔轮廓，收掉积木接口；保留成人男性宽肩与自然肤色面。
- 交领改为贴体曲面带，束发改为一体扫掠发盖、软束髻和干净发尾。正常画幅只保留可读的大形和值域，去除高频小饰物噪点。
- 独立实体剑具有加宽的双面剑锋和可见剑脊，不依赖发光线冒充刀刃。

正常手机画幅角色仍然很小，不能拿三角数、骨骼数或近景截图当成美术质量通过。`qa-h31-character/normal-h30-same-env.png`与`normal-h31-same-env.png`已按同一场景、同一出生位、同一机位、390×844并列检查；最终应以整屏走位、转身和挥剑的艺术观感为准。

## 接入API保持不变

```js
const hero = createHero();
player.add(hero.group); // local+Z forward
hero.update(dt,{moving,speed,attackProgress});
```

`attackProgress=null`为非攻击；0..1为完整剑招。周期`.78s`、命中阈值`.44`。在右侧抬剑→前扫→左侧随势→收势中，实体剑与手腕保持连续。`swordTipWorld(out?)`、`bladeBaseWorld(out?)`和独立`sword`供现有剑光跟随。转身未传`turn`时自动从父级世界朝向计算。角色模块不移动人物、不改相机、不自行扣敌血。

本轮也调查了CC0男性底模和动作资源，但VRoid官方男性样件是现代衣发，Quaternius人体仍需制衣，均没有原样进入游戏。后续若使用应单独保留文件内授权、原作者页面及改造记录，不能把任意西式/日式角色重着色就称为林砚。

## H32 启动预烘焙与等价验证

运行时不再执行 SDF / marching tetrahedra、曲面采样、计算法线或材料桶合并。`getBakedHeroData()` 首次调用解码原始 TypedArray，后续复用只读数组；每个实例仍有独立的 22 骨骨架、材质、独立实体剑和动作状态。模型维持 16,798 个三角形、7 材质、1.485 高；没有替换成 H30 或简化外形。

自有完整源和离线导出不依赖 DOM / WebGL。在仓库根目录运行：

```sh
node .github/scripts/bake-linyan.mjs
node .github/scripts/verify-linyan-bake.mjs /tmp/linyan-bake-verification.json
```

`manifest.json` 记录生成源和 19 个几何属性/索引数组的 SHA256、类型、大小，以及原始 Float64 inverse bind。预烘焙模块 1,061,920 字节，gzip 349,822 字节；几何原字节 784,456 字节。没有量化、重排顶点或减面。

验证同时比较原生成器与生产模块的材料/骨架、原始绑定矩阵，以及 76 个正常待机、走路转身、出剑、命中、随势和收势姿态。每帧比较骨矩阵、实际蒙皮抽样和世界空间剑基/剑尖；本次最大绝对误差为 0。命中帧只更新必需的手臂祖先链，消除重复全树遍历，保留即时实体剑查询正确性。

云端 Node v24.22.3 CPU 测试中，首次构造 151.25→4.42 毫秒（后者含首次解码），12 次预热中位数 55.28→0.452 毫秒。此数据仅描述该机器上的角色构造开销，不是 iPhone 性能或整场景帧率，也不能据此判断全部启动问题已经解决。浏览器/WebKit 的完整启动与正常玩法验收另外记录。
