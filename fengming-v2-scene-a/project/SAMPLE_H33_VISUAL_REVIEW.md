## 三个问题

| 问题 | 图片本身能看到什么 | 判断与限制 |
| --- | --- | --- |
| 第一眼是否像持剑侠客？ | 出生整屏中央的朱红衣、深色束发、米色领/腰部及从手延伸的银色实体剑，与青灰石地和墨绿环境分开。剑长与手臂位置可辨。 | **基本可辨为国风持剑人物。** 不是无武器的小红块。人物仍很小，躯干/袖有方块感，面部、成年男性特征和衣料细节在整屏不能充分读出；不应把近看造型或骨骼技术当作这些细节已完成的证明。 |
| 穿枝、登阶是否有清楚空间关系？ | `under-branch.png` 的红色身体处于较低横枝之下，前枝局部遮住头肩附近，身体仍露出；树根、路面、枝冠有不同前后位置。`step-top.png` 的角色位于山门右侧一组实际可见的窄踏步上，低处灰敌在其右下方。 | **这些站位画面的前后/高低关系可读。** 没有整个人被树或屋檐抹掉。屋檐侧边留给人物的视觉出口依然窄，阶梯不是画面中很宽敞的主路。静态图不能证明连续走位、碰撞或流畅度，应由原速实走录像另外证明。 |
| 关 FX、排除血条后能否仅凭动作认出命中？ | `01` 剑伸向左侧预备；`02` 白色实体剑向右下的敌人扫下；`03-contact` 剑刃跨过灰敌头肩边缘，敌人位置/姿态随之退向右下；`04` 剑继续向右上随势；`05/06` 剑与手臂收回。不是只有发光弧线或文字在变。 | **连续六帧可读成一次挥剑击中并收势。** `03` 的接触只占数像素，孤立该图不足以解释完整动作；要连同 `02/04` 看剑向与敌人反应。最终正常 UI 复图中，敌人名字/血条已移到敌人右上空处，不再压住这组图里的剑、手或敌头肩。 |

## 对照中确实改善的部分

H31/H33 正常镜头并排图中，H33 的松干、针叶团、石地和屋檐由较重的碎纹理改为更大的明暗块，环境噪声减少，红衣人物更容易从地面分离。迎客松的弯干、主分叉、向路面横伸的枝条和冠层空隙清楚，横枝与右侧屋檐间仍有可见空隙。屋面曲面连续，近路面的石板接缝与通行带更明确。这些变化在整幅手机画面里可见，无需拉近模型。

初审发现的敌人名字/血条贴近战斗区域问题已修复并复图确认：最终 `step-top.png` 与 `sample-after-hit.png` 中，HUD 位于敌人右上方空地，与红衣人物、持剑手、实体剑和敌头肩留出可见间隔；`sample-before.png` 中画外敌人 HUD 未留在画面边缘。该遮蔽不再列为最终版限制。

## 仍需如实呈现的不足

- 这轮达到的是“三项基本可读”，不能据此宣称已达到 Frog Ferry／Slackwater 的整体美术完成度。人物头身/袖口依然概括，地面与背景山体也仍有较大的平面和程序化形状。
- 屋檐侧边的可见通道较窄。虽然该站位能看到人物与剑，不能从单张图推定其他稍偏的点击位置也同样舒适或无遮挡。
- 六张动作静帧能证明不同姿势和接触关系，不能单独证明动作播放自然、不卡顿或设备流畅。以原速录像和实际设备测试分别说明。

本审查没有看到使三项核心内容完全读不出的帧；最弱的是 `03-contact` 的数像素接触。最终正常 UI 的血条位置已实看确认不再压住接触区域。交付时应保留原整屏、连续动作序列和正常 UI 实走，而不是只交近景或单张命中截图。
