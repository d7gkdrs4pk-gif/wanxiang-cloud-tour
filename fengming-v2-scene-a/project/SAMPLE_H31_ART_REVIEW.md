# H.31：按 Frog Ferry / Slackwater 重审与修订

用户对 H.30 的结论是“画面太粗糙，和演示视频质量差太多”，并明确主要参考为 Frog Ferry／Slackwater。该结论优先于此前可运行、动作齐全等技术记录；H.30 美术未通过。

## 实际对照了什么

- [Frog Ferry 官方游戏](https://frogferry.chirostudio.xyz/)：实际进入 Lagoon / Day Mode，以390×844画幅操作船移动、转向。船边、木条有明确厚度与统一光照；水下物体降对比；前后植被、石头、桨与涟漪在移动时一起提供空间和动作反馈。
- [Slackwater 官方演示](https://raea.io/made/)（Shane / Raea 的30秒垂钓演示，非其他同名游戏）：查看[官方原视频](https://media.raea.io/made/slackwater.mp4)与[官方静帧](https://media.raea.io/made/slackwater.jpg)。其船、人物、岩石和植物的绘画语言统一，光向、接触影、水下染色与局部亮点共同服务主体。

对照用于批评与美术方向研究，未把两个游戏的图片、模型或代码导入游戏素材。不能把参考的不同镜头、主体比例或 GPU 条件当作本工程的同机位性能对照。

## H.30 的实际问题与本轮处理

| 问题 | H.31 实际改动 |
| --- | --- |
| 旧地面像破碎扫描图，调暗后仍是灰色乱面 | 自制手绘石板/岩石两格纹理，真实地形的地面按世界XZ投影，坡壁用三向岩纹；平缓无意义的上向碎法线 |
| 前景大面积空地，缺少疏密与活动区 | 入口石带、门前石坪、松旁与右阶通路分别保留，两侧过渡墨绿苔岩；在边界放真实接地的蕨草、矮石，保持原路线 |
| 山门、树图、几何山峰不属同一套美术 | 清理瓦/木色，保留82%原UV明暗及深檐体积；近建筑不吃远景雾；替换为两层自有手绘远山 |
| 肩背、手、衣摆像拼装占位件 | 男主上衣重做连续柔弧肩袖，手靴圆融，厚袍与纵褶用连续权重弯曲；束发/交领保留清楚大形，实体剑锋加宽 |
| 树根和灯像摆上去的零件 | 根影按真实地形贴合并扩大；同画风矮石和植物收边；原灯位换八角石灯，使用少量暖芯光 |

第一轮 H.31 曾因石板重复铺满、屋檐被压色压平而被内部退回；没有把该轮截图或“加载成功”当成美术验收通过。最终仍需用户在正常手机玩法镜头判断是否达到期望的整体完成度。

## 保留的约束

FOV39、跟随偏移(6,27,15)、原人物高度1.485、原出生站位(-3.2,ground,-4.2)和朝向不变。原地形、gate的真实低台阶、navigation.json、.72树根碰撞、攻击范围/伤害判定均复用。不是把整座山门变成一张背景，也没有靠拉近相机制造升级。

H.29原正式index.html未改。H.30源完整存于sample-h30/，h30-compare.html可以单独操作；新修订继续从sample-gate.html进入。

## 资源与验证

新地面、岩石及远山为本项目新制 ImageGen 生产资源，见 assets/environment-031/provenance.json。角色、植被、石灯和着色实现自有；本轮调查过的VRoid/Quaternius等候选未导入游戏。保留Three.js r170及MIT许可。

最终正常画幅、连续触控录像和运行数据见 evidence/h31/。云端Linux/Chromium156/SwiftShader为软件渲染手机尺寸模拟；不代表iPhone或微信真机测试结果。技术数据用于排查加载、碰撞和动作，不能替代美术判断。

最终走测记录：原速视频14.80秒，连续操作完成走近古松→从前枝下穿过→绕门前→登真台阶→回身普通挥剑命中→收势。敌生命3→2，脚下高度0.708041，错误0/请求失败0。118个渲染帧覆盖14.241秒，平均8.216FPS，中位帧间隔115ms、P95为261.40ms；视频25FPS编码不是游戏帧率。同位比较首帧相机和人物位置最大轴差均为0，见normal-camera-proof.json。

实录：`../evidence/h31/sample-walk-sword.mp4`；整幅比较：`../evidence/h31/h30-h31-normal.jpg`；连续数据：`../evidence/h31/sample-playtest.json`。H31仍保留原镜头下约36px的人物尺寸，不能借近摄特写宣称脸部细节已达到参考品质。
